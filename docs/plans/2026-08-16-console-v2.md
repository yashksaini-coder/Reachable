# Console v2 — services registry, live Ask chat, graph view, setup

Owner review of the first console (2026-08-16 17:00 IST) — decisions taken:

1. **`seeds.json` is gone as a concept.** Services live in the graph. They are added through the
   UI (Add repository → job) or `make add REPO=owner/repo`. `demo/services.txt` and
   `demo/incidents.txt` are plain lists that *replay* those commands so a judge can reproduce
   the gallery; they are not configuration the code reads.
2. **Fresh graph.** Store wiped, node restarted with the owner's token from `.env`, worker reads
   the same `.env`. Everything re-ingests from the on-disk HTTP cache.
3. **No HydraDB "dashboard".** The hosted product's dashboard cannot see an OSS `graph-node`.
   The console gets a **Graph** page instead: counts, ingest jobs, and a rendered blast-radius
   graph per incident. This is *our* model on screen, not a vendor screen.
4. **UI corrections from the screenshots:** the header Ask bar goes (Ask is a page); the home
   page becomes an incident **list** (no half-empty card grid), the three principle cards move to
   the README; Services rows become uniform (note in a tooltip); Ask becomes a **chat**.
5. **Setup commands** collapse to `make up` (node + api + web), `make add`, `make incident`,
   `make reset`, `make demo`.

## Contracts (fixed before the fan-out; every agent codes to these)

### Worker API (`worker/reachable/api.py`, loopback :8787)

```
GET  /health                              {ok, services, ms}
GET  /services                            [{key, name, repo_url, criticality, lockfiles, latest_commit, added_at?}]
POST /services/add   body {"repo":"owner/repo" | "https://github.com/owner/repo"}
                                          -> 202 {job_id}   (400 on bad slug; 409 if a job for it is running)
GET  /jobs                                [{job_id, repo, status, started_at, ended_at, step, steps:[{name,status,ms,detail}]}]
GET  /jobs/<id>                           same, plus log:[...last 200 lines]
GET  /graph/stats                         {nodes:{Service,Lockfile,Package,Version?,Advisory,Maintainer,File}, edges_written:{…from last jobs}, last_ingest}
GET  /ask/*  and /cypher                  unchanged
```
Job steps, in order: `lockfiles` (github.ingest_service) · `packages` (npm enrichment for new
versions) · `advisories` (OSV querybatch for the repo's versions + affects) · `reach` (import scan
at latest commit) · `done`. One job at a time (single-threaded engine access); others queue.
Jobs live in memory + `.cache/jobs.jsonl` append log so a restart shows history.

### Web

- `web/lib/api.ts` gains `services()`, `addService(repo)`, `jobs()`, `job(id)`, `graphStats()`.
- Routes: `/` incidents list · `/incident/[advisory]` (+ Graph section) · `/incident/[advisory]/[...service]` ·
  `/board` · `/services` (list + Add repository form + job progress) · `/graph` (stats + jobs) ·
  `/ask` (chat) · `/api/ask` (POST proxy) · `/api/services` (GET/POST proxy) · `/api/jobs/[id]` (GET proxy) ·
  `/badge/[owner]/[repo]` · `/api/health`.
- No event/track copy anywhere in the UI.

### Makefile
`make up` (starts node in Docker detached? — no: node stays foreground in its own terminal; `make up`
starts api+web and prints the node instruction if :7687 is closed) · `make add REPO=` · `make incident ID=` ·
`make reset` (stop node, archive store, restart) · `make demo` (replays demo/*.txt) · `make test`.
