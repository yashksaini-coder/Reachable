# Plan — the guide as a story that wins on evidence

## Goal
Turn `/docs` from "what each page shows" into a four-chapter guide, judged-first: **Why a graph →
How it works → Using it → Reference**. Every claim is tied to an executed statement or a measured
number pulled from the committed report JSON at build time (never typed by hand). Precise
diagrams are inline SVG in the design tokens; chapter openers are pixel art you generate; three
GIFs are recorded from the console.

## Information architecture (URLs stay under /docs)
| slug | title | source file | openers / diagrams / gifs |
|---|---|---|---|
| `why` | Why a graph | docs/console/why.md | opener `why.png` · diagram `six-questions` |
| `how-it-works` | How it works | docs/console/how-it-works.md | opener `how.png` · diagrams `pipeline`, `schema`, `q1-walk`, `q3-window`, `q4-fanout`, `q5-nearnames` |
| `using` | Using it | docs/console/using.md | opener `using.png` · gifs `add-repo`, `ask`, `export-pdf` |
| `reference/schema` | Graph schema | docs/schema.md | — |
| `reference/ask` | Ask grammar | docs/console/ask.md | — |
| `reference/run` | Running it | docs/console/run.md | — |
| `reference/data` | Data & limits | docs/console/data.md | — |
`overview.md` and `pages.md` fold into `why.md` / `using.md` and are deleted; `lib/docs.ts` DOCS
gets sections (Guide: why · how-it-works · using — Reference: schema · ask · run · data); the
`/docs` index redirects to `/docs/why`.

## Marker contract (renderer, `web/lib/docs.ts` + `web/components/docs/*`)
- `{{diagram:NAME}}` on its own line → the React SVG component `components/docs/diagrams/NAME.tsx`
  (server component, tokens only, `<title>`/`aria-label`, ≤ 900 wide, scrolls in its card).
- `{{stat:PATH}}` inline → a number from `worker/out/MAL-2025-46974.json` (e.g. `headline.services_exposed`,
  `q1_exposed.timing.warm_p50_ms|ms`, `provenance.graph.Version|int`), formatted; missing → the literal
  `— not computed`. `{{cypher:SECTION}}` → the executed statement block for `q1_exposed`, `q1_mspaths`,
  `q2_versions`, `q3_while_live`, `q4_maintainers`, `q5_typosquats.<pkg>` rendered as `<pre>`.
- `{{figure:FILE|caption}}` → `docs/assets/guide/FILE` (png/gif) with a caption; missing file → the
  caption alone in a dashed slot (never a broken image).
Implementation: markdown → html via marked as today; markers are replaced BEFORE marked with
placeholder tokens and swapped for React nodes after (split html on placeholders, interleave).

## Chapter outlines
### why.md
1. The incident in one paragraph (2025-09-08, 18 packages, ~2B weekly downloads, ~95 min live).
2. The six questions — each one sentence, and *why it is a traversal, not a table scan*.
3. `{{diagram:six-questions}}` — one graph, six coloured walks.
4. What breaks without the graph (Q3 bitemporal join; proof paths; N×M in one call).
5. Verdicts (four, semantic colours), and the honesty rules (upper bound · not computed · unscanned).
### how-it-works.md
1. Pipeline `{{diagram:pipeline}}`: GitHub lockfile history (npm v2/v3, pnpm v6/v9) → registry → OSV →
   import scan → HydraDB; counts `{{stat:provenance.graph.*}}`.
2. Graph model `{{diagram:schema}}`: node labels, edges with the properties that matter (`AFFECTS.live_from/live_to/live_to_kind`, `RESOLVED.at`, `NAME_SIMILAR_TO.kind/distance`), integer ids.
3. Q1 `{{diagram:q1-walk}}` + `{{cypher:q1_exposed}}` + `{{cypher:q1_mspaths}}` + timings.
4. Q2 + `{{cypher:q2_versions}}`; removed versions from the registry time map.
5. Q3 `{{diagram:q3-window}}` + `{{cypher:q3_while_live}}` + evidence classes + timing.
6. Q4 `{{diagram:q4-fanout}}` + `{{cypher:q4_maintainers}}` + the cap.
7. Q5 `{{diagram:q5-nearnames}}` + statement + hypothesis note. 8. Q6/verdicts + reachability scan.
9. What we learned about the engine (probe facts) — 10 bullets from AGENTS.md §8.
### using.md
1. `{{figure:add-repo.gif|…}}` add a repository → four steps → service in the graph.
2. Read the report card by card (six cards, one line each) → `{{figure:export-pdf.gif|…}}`.
3. Ask `{{figure:ask.gif|…}}` (grammar table lives in reference/ask). 4. Board. 5. Beyond the watched set.
6. Coding agents (MCP tools list). 7. Badge. 8. Read-only deploys / degraded states.
